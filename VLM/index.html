1把视觉接进语言模型：三种接法

语言模型的世界里只有一件事：给定前面的 token，预测下一个。图像要进来，必须先被翻译成这个世界的居民。所谓视觉语言模型（VLM），本质上只在回答一个工程问题——怎么翻译，以及翻译这件事要花多少代价。

这个问题的难点不在"能不能对齐"，而在三者的相互牵制：

约束含义放宽它的代价
视觉 token 预算一张图要用多少个 token 表示太多会挤占上下文、拖慢推理；太少会丢细节
可训练参数量为了接上视觉，需要改动多少权重改得越多，越可能破坏 LLM 已经学到的语言能力
上下文学习能力能否像 GPT 那样靠 prompt 里的示例现学新任务要保住它，训练数据必须是交错排列的多图文序列，而这类数据昂贵

过去三年的主流方案，恰好可以按"视觉在什么位置与语言汇合"分成三类。下面这张图把三种接法放在同一张坐标系里对照——每一行从左到右都是"视觉编码器 → 桥梁 → 冻结的 LLM"，区别只在中间那一段，以及视觉信息在 LLM 内部从哪里进入。

三种接法的核心差异集中在一个位置上：视觉 token 是插进 LLM 的层里（Flamingo），还是作为前缀拼在输入前面（BLIP-2 / LLaVA）。前者改的是架构，后者改的是接口。

一条贯穿全章的主线

从 Flamingo 到 BLIP-2 再到 LLaVA，可训练的模块一路变少（10.2B → 188M → 20M），但塞给 LLM 的视觉 token 一路变多（插层 → 32 → 576）。这两条曲线是反向的，而最后的胜负说明：在数据足够的前提下，让 LLM 直接看到更多原始信息，比精心设计的压缩结构更有效。

2Flamingo：在冻结的 LLM 内部开一扇窗

Flamingo（DeepMind，2022）的问题意识很明确：能不能让一个已经训练好的 LLM 学会看图，同时不破坏它的 few-shot 能力？

朴素的微调做不到这一点——一旦用图文数据全量微调，LLM 的语言能力会退化，上下文学习也会失效。Flamingo 的答案是不动 LLM 的权重，而是往它的层间插入新的、可训练的交叉注意力模块，并让这些模块在训练初期"等于不存在"。

2.1 三个组件

组件作用是否训练
视觉编码器（NFNet-F6）把图像变成特征图，再拉平成变长的 patch 序列冻结
Perceiver Resampler把任意长度的视觉特征压缩成固定 64 个 latent 向量训练
Gated Cross-Attention插在冻结 LLM 的层间，让文本 token 能查询视觉 latent训练

2.2 门控：让新模块从"零作用"开始

交叉注意力层的输出被一个门控量控制，形式极简：

$$\mathbf{y} = \mathbf{x} + \tanh(\alpha) \cdot \mathrm{CrossAttn}(\mathbf{x}, \mathbf{V})$$

关键在于 $\alpha$ 被零初始化。训练第一步时 $\tanh(0) = 0$，整个模块输出为 $\mathbf{x}$，也就是恒等映射——一个刚插入的、行为完全无害的模块。随着训练推进，$\alpha$ 逐渐离开零点，视觉信息才开始一点点渗入。

交叉注意力本身是标准的缩放点积形式，只是 query 来自文本，key 与 value 来自视觉 latent：

$$\mathrm{CrossAttn}(\mathbf{x}, \mathbf{V}) = \mathrm{softmax}\!\left(\frac{\mathbf{Q}_\text{text}\mathbf{K}_\text{vis}^{\top}}{\sqrt{d}}\right)\mathbf{V}_\text{vis}$$

Perceiver Resampler 用的也是同一个算子，区别在于它的 query 是一组可学习的 latent，数量固定为 64——正是这个固定数量，让后续的 LLM 无论面对多少张图、多高分辨率，收到的视觉 token 数都不变。

这个设计的价值在 ViT 之后被反复验证：往一个已经训练好的网络里加新模块，最难的不是让它有用，而是让它一开始不添乱。零初始化门控（以及后来 ResNet 的零初始化残差分支）解决的是同一个问题。

2.3 交错图文数据：few-shot 能力的来源

Flamingo 能靠 prompt 里的几个示例现学新任务，不是因为架构，而是因为训练数据的形式。它使用了大规模交错图文数据（图文按网页阅读顺序自然穿插），模型因此见过"一个序列里有多个图文对"的样本，学会了在序列内建立跨样本的关联。

这一点直接决定了 BLIP-2 的短板

BLIP-2 的训练数据每条样本只有一个图文对，LLM 从未见过"序列内多个图文对"的形态，因此无论怎么微调都无法获得上下文学习能力。这不是参数量的差距，是数据形式的差距。第 3 章会看到论文自己把这一点列为局限。

3BLIP-2：只训一个翻译官

Flamingo 要在 LLM 内部插新层，意味着必须改动架构、且训练时要穿透 LLM 反向传播。BLIP-2（Salesforce，2023）换了个思路：能不能把视觉编码器和 LLM 同时冻结，只训练中间那个翻译官？

这就是 Q-Former（Querying Transformer）的由来。它用一组可学习的 query 向量去"问"视觉特征，把答案整理成固定长度的向量交给 LLM。

3.1 32 个 query 的瓶颈设计

冻结的 ViT 输出 257×1024 的特征（196 个 patch 加上 CLS），而 Q-Former 只输出 32×768。这是一个刻意为之的信息瓶颈：出口比入口窄得多，query 被迫只保留"对语言最有用"的那部分信息，天然过滤掉视觉噪声。

$$\underbrace{257 \times 1024}_{\text{ViT 输出}} \;\longrightarrow\; \underbrace{32 \times 768}_{\text{交给 LLM}} \qquad \text{压缩比约 } 10.7\times$$

32 这个数字来自消融：从 16 增到 32 有提升，再增到 64 收益已经很小。附带的好处是推理成本固定——无论输入图像多大，交给 LLM 的永远是 32 个 token。

3.2 两阶段训练

第一阶段完全不碰 LLM，只训 Q-Former，用三个共享 query 的损失：

目标做了什么为什么要它
ITC
图文对比		把 query 输出与文本 [CLS] 做对比学习，相似度取 32 个 query 中的最大值建立全局的图文对齐。取最大值而非平均，是为了"只要有一个 query 对齐上就算对齐"
ITM
图文匹配		二分类判断图文是否配对，使用硬负样本挖掘提供细粒度判别力，专门挑最难区分的负样本训练
ITG
图生文		以 query 为条件自回归生成描述强制 query 装下"可被语言描述"的信息——这条对检索任务也有增益

第二阶段才接上冻结的 LLM，用一个线性层把 32×768 投到 LLM 的嵌入维度，作为软视觉提示拼在文本嵌入前面，只训 Q-Former 与这个投影层。

左侧是瓶颈的几何直觉：无论输入多宽，出口只有 32 个向量。右侧是两阶段的分工——阶段一解决"怎么看"，阶段二解决"怎么向 LLM 汇报"。跳过阶段一会让 LLM 收到读不懂的向量，论文报告会出现灾难性遗忘。

为什么两阶段不能合成一步

如果一开始就把未对齐的视觉特征塞给 LLM，LLM 面对的是它从未见过的向量分布，梯度会把两个模块同时往错误方向推。阶段一先用纯视觉-语言目标把 query 训练成一个"语言友好"的压缩器，阶段二再在那之上教它对接 LLM——这是典型的课程学习思路。

3.3 结果与代价

论文报告：零样本 VQAv2 上超过 Flamingo-80B，而可训练参数少 54 倍（188M 对 10.2B）。但代价也很明确：

  • 无上下文学习——训练数据每条只有一个图文对，见不到序列内的示例关联
  • 生成质量受 LLM 拖累——LLM 的知识错误与推理错误会原样传导到输出
  • 继承 LLM 的风险——偏见、有害语言等问题一并继承

4LLaVA：把对齐问题换成指令微调问题

LLaVA（2023）的做法在当时颇具争议：它删掉了 Q-Former，只留一个两层 MLP 把 CLIP 的 576 个 patch token 全部投到 LLM 空间，然后交给 LLM。

压缩率明显更差——576 个 token 是 BLIP-2 的 18 倍，上下文很快被填满。但 LLaVA 赌的是另一件事：只要给足指令数据，让 LLM 自己去看原始 patch 比精心压缩更有效。

4.1 两步走

步骤数据训练什么目标
特征对齐558K 图文对（CC3M 筛选）只训两层 MLP让 576 个视觉 token 落到 LLM 能读的语义位置
视觉指令微调158K GPT-4 生成的多轮对话解冻 LLM，视觉编码器仍冻结教会模型按人类预期的方式回答，覆盖问答、描述、复杂推理

第一步只解决模态对齐，成本极低但不产生任何指令遵循能力。第二步才是 LLaVA 真正的贡献——它把"视觉对话"变成了一种可以用纯文本格式表达的训练任务：一张图加上几句对话，就是一条训练样本。

两种前缀型方案的视觉 token 数量差了一个数量级，这直接决定了上下文预算的分配：

$$L_\text{seq} = \underbrace{N_\text{vis}}_{\text{BLIP-2: }32 \;\mid\; \text{LLaVA: }576} + N_\text{text}, \qquad \text{24}{\times}\text{24 patch 网格} \Rightarrow 576$$

4.2 为什么"简单方案"赢了

LLaVA 的胜利可以拆成三个原因：

  1. 压缩不是目的，对齐才是。BLIP-2 的瓶颈牺牲了细节换取 token 效率，但 VQA 类任务恰恰需要细粒度视觉信息（小字、纹理、空间关系）。
  2. 指令数据的质量比架构更稀缺。用强模型（GPT-4）生成 15 万条多轮对话，成本远低于训练一个复杂的 bridge，收益却立竿见影。
  3. 架构越简单越容易扩展。没有 Q-Former 的交叉注意力，多图、视频、任意分辨率都只是"多拼几个视觉 token"的问题。
与 BLIP-2 的取舍

Q-Former 并没有被淘汰——在 token 预算紧张的场景（长视频、多图、端侧）它仍然不可替代。业界的实际分工是：预算充足时用全量 patch，预算紧张时用 query 压缩。这不是对错之争，是资源约束下的不同选择。

5.1 选型建议

  • 需要 prompt 里给示例就学新任务 → Flamingo 路线（交错的训练数据是硬门槛）
  • 上下文窗口紧张、图像数量多 → Q-Former 路线
  • 要做通用的视觉对话助手 → LLaVA 路线，把预算花在指令数据上
一个常被忽略的判据

选型时先问"我的视觉信息有多细"。如果任务需要读小字、认纹理、判断精确空间关系，压缩型 bridge 会先损失掉这些信息，再多的训练也补不回来。瓶颈一旦形成，就是信息论意义上的损失。

6工程实现

6.1 Q-Former 的骨架

Q-Former 的核心是"query 之间做自注意力、query 对图像特征做交叉注意力"。下面是一个最小实现，保留了原设计的关键点：query 是可学习参数、交叉注意力每隔一层插入、文本路径不接图像。

qformer.py — 32 个可学习 query 如何抽取视觉信息
import torch
import torch.nn as nn


class QFormerLayer(nn.Module):
    """自注意力只在 query 之间；交叉注意力让 query 去查图像特征"""

    def __init__(self, dim, heads, cross_every=2):
        super().__init__()
        self.self_attn = nn.MultiheadAttention(dim, heads, batch_first=True)
        self.cross_attn = nn.MultiheadAttention(dim, heads, batch_first=True)
        self.cross_every = cross_every
        self.norm1 = nn.LayerNorm(dim)
        self.norm2 = nn.LayerNorm(dim)
        self.mlp = nn.Sequential(nn.Linear(dim, 4 * dim), nn.GELU(), nn.Linear(4 * dim, dim))

    def forward(self, queries, image_feats, use_cross):
        q = queries + self.self_attn(self.norm1(queries), self.norm1(queries), self.norm1(queries))[0]
        if use_cross:  # 每隔 cross_every 层插一次交叉注意力
            q = q + self.cross_attn(self.norm2(q), image_feats, image_feats)[0]
        return q + self.mlp(q)


class QFormer(nn.Module):
    def __init__(self, num_queries=32, dim=768, depth=12, heads=8, vision_dim=1024):
        super().__init__()
        # 32 个 query 是模型参数，不是输入——同一个 query 用于所有图像
        self.queries = nn.Parameter(torch.randn(num_queries, dim) * 0.02)
        self.proj_vision = nn.Linear(vision_dim, dim) if vision_dim != dim else nn.Identity()
        self.layers = nn.ModuleList([QFormerLayer(dim, heads) for _ in range(depth)])

    def forward(self, image_feats, batch_size):
        """image_feats: (B, 257, 1024) -> 输出 (B, 32, 768)"""
        v = self.proj_vision(image_feats)
        q = self.queries.unsqueeze(0).expand(batch_size, -1, -1)
        for i, layer in enumerate(self.layers):
            q = self.layers[i](q, v, use_cross=(i % 2 == 0))
        return q

6.2 三种 bridge 的统一接口

抛开实现细节，三者的差别可以压成一个函数签名：把视觉特征映射成"LLM 能读的前缀 token"。

bridges.py — 三种桥梁的等价形式
import torch
import torch.nn as nn


class QFormerBridge(nn.Module):
    """BLIP-2：压缩到 32 个 token，交给 LLM 的只有这些"""

    def __init__(self, vision_dim=1024, llm_dim=4096):
        super().__init__()
        self.qformer = QFormer(num_queries=32, vision_dim=vision_dim)
        self.to_llm = nn.Linear(768, llm_dim)

    def forward(self, image_feats, batch_size):
        return self.to_llm(self.qformer(image_feats, batch_size))


class MLPBridge(nn.Module):
    """LLaVA：不压缩，576 个 patch 全部投影过去"""

    def __init__(self, vision_dim=1024, llm_dim=4096):
        super().__init__()
        self.net = nn.Sequential(nn.Linear(vision_dim, llm_dim), nn.GELU(), nn.Linear(llm_dim, llm_dim))

    def forward(self, image_feats, batch_size):
        return self.net(image_feats)      # 形状 (B, 576, llm_dim)


def prepend_visual(visual_tokens, text_embeds):
    """两种前缀型 bridge 共用的拼接方式"""
    return torch.cat([visual_tokens, text_embeds], dim=1)
实现上的两个坑

一是注意力掩码：视觉 token 必须对后文可见，但文本 token 不应该反过来影响视觉 token 的表示（否则视觉表征会被答案污染）。二是位置编码：拼接后文本的位置 id 必须整体后移，否则 LLM 会认为视觉 token 和句首文字在同一位置。

7知识体系总结

层次要回答的问题代表工作关键机制
1 表示对齐图像怎么变成 LLM 能读的向量CLIP对比学习拉近配对图文
2 接口设计视觉向量以什么形式、多少数量进入 LLMFlamingo / BLIP-2 / LLaVA插层 vs 前缀；压缩 vs 全量
3 行为塑造模型怎么学会按人类预期回答LLaVA视觉指令微调
4 行动输出怎么从"看懂"走到"会做"RT-2 / π0动作 token 化 / 流匹配

本章的三条路线覆盖了第 1 到第 3 层。第 4 层是下一章的主题：一旦模型能稳定地把图像映射进语言空间，下一个问题自然就是——能不能让它的输出不只是词，而是动作。

归纳成一句话

VLM 的全部设计空间，就是在"给 LLM 看多少"与"自己要改多少"之间找平衡点。Flamingo 选了改架构、保住上下文学习；BLIP-2 选了最小改动、牺牲 token 数量；LLaVA 选了最简架构、把复杂度转移到数据上。没有唯一正确答案，只有与资源约束匹配的答案。
